Visualization¶

The reference for stream.viz. Plot a sweep shows how to use it, one task at a time.

cases(**levels)[source]¶

Use this to lay out every combination of parameter levels you want solved.

The product of the given levels, one dict per case.

Each keyword is a parameter and its levels; a single number or string is a parameter with one level. The last parameter varies fastest:

cases(power=[2e6, 4e6], mdot=[0.2, 0.3], Tin=300.0)

gives four cases, power=2e6, mdot=0.2 first. Pass the list to run_cases, then the list and the frames to Sweep.

Return type:

list[dict]

run_cases(model, cases, catch=(<class 'stream.solvers.AlgRuntimeError'>, <class 'stream.solvers.TransientRuntimeError'>, <class 'stream.calculations.channel.SaturationReachedError'>), mapper=<class 'map'>)[source]¶

Use this when one function solves one case, to solve the whole grid in order and keep the failures as holes.

Solve every case with model(**case) and collect the frames for Sweep.

frames = run_cases(model, cases_)
sweep = Sweep(cases_, frames, agr)
Parameters:

  • model (Callable[[...], DataFrame]) – Called as model(**case) for every case; returns that case’s State.to_dataframe().

  • cases (Sequence[Mapping[str, float | str]]) – One dict per case, as cases makes them.

  • catch (tuple[type[BaseException], ...]) – The exceptions that make a case a hole. The default holds the three ways a STREAM solve reports that it did not finish: AlgRuntimeError and TransientRuntimeError from stream.solvers and SaturationReachedError from stream.calculations.channel. Only these become holes; any other exception, a bug in the model among them, propagates.

  • mapper (Callable) –

    How the cases are run: any map that keeps the order of the cases, called as mapper(f, cases). The model is called in the mapper’s workers. The builtin map (the default) runs the cases one after the other. A process pool (ProcessPoolExecutor().map or multiprocessing.Pool.map) pickles the model, so it must be a module-level function; threads and dask take any callable:

    from concurrent.futures import ProcessPoolExecutor, ThreadPoolExecutor

with ThreadPoolExecutor() as pool:
    frames = run_cases(model, cases_, mapper=pool.map)
with ProcessPoolExecutor() as pool:
    frames = run_cases(model, cases_, mapper=pool.map)
frames = run_cases(model, cases_, mapper=lambda f, xs: dask.compute(*(dask.delayed(f)(x) for x in xs)))

Returns:

One frame per case, in the order of cases, with None in the slot of a hole. Its failures maps the index of each hole to the exception text, and one warning lists every failed case.

Return type:

list

Notes

Uncertainty enters through the model: a model that returns its state’s frame with uq_attach bands (sys and stat columns) gives a banded sweep.

class Sweep(cases, frames, agr, labels=None, limits=None, fill_holes=False)[source]¶

Use this to ask questions of steady states solved over a grid of design parameters.

Cases, result frames and the aggregator they came from.

Build one from your own loop or from cases and run_cases, then ask it a question, profile, field, reduce (two parameters on versus make a map) or required, and call .plot() on the answer or read its frame. What is true of the whole sweep is set here: labels, limits and whether holes are filled:

cases_ = cases(power=[2e6, 4e6, 6e6], mdot=[0.2, 0.3])
frames = run_cases(model, cases_)
sweep = Sweep(cases_, frames, agr, limits={"CHFR": at_least(1.3)})

Ask print(sweep) for the parameters and their levels, the quantities of each calculation, the holes and the limits. The sweep keeps its data readable: cases, frames, the aggregator agr, the stacked table, holes, filled, limits and labels.

Parameters:

  • cases (Sequence[Mapping[str, float | str]]) – One dict per case, all with the same keys. A value is a number, or a string for a parameter that is a choice (a wall law, a correlation); each parameter is one or the other in every case. A choice can colour, style or panel a figure, never be an axis.

  • frames (Sequence[DataFrame | None]) – One State.to_dataframe() result per case, or None for a case whose solve failed (a hole). The list run_cases returns also carries each hole’s message.

  • agr – The aggregator, static across the sweep, used for coordinates.

  • labels (Labels | Mapping | None) – A Labels, or a mapping from name to a Label or its shorthand tuple: display names, units and scales, merged over the module defaults.

  • limits (Mapping[str, Limit] | None) –

    The limits the design must respect, one per quantity:

    limits={"CHFR": at_least(1.3), "T_clad": at_most(900.0)}

    A declared limit is drawn on every figure that shows the quantity, gives required its target and limiting=True its meaning. Quantities that share axes and one limit get one line between them.

  • fill_holes (bool) – True fills a hole when, along a numeric parameter and with every other parameter equal, the grid levels immediately below and above it are solved cases; the fill interpolates linearly between the two (the mean over the parameters that bracket it). A hole that no numeric parameter brackets this way (at the edge of the sweep, or next to another hole, along every one of them) stays a hole. Filled rows carry filled=True in every frame, draw with an open marker (a field ends its subtitle with , interpolated) and are listed in filled. Off by default because an interpolated case is a guess.

profile(quantity, of=None, where=None, nearest=False, sigma=1.0, uncertainty=True)[source]¶

Use this to see how a quantity varies along the channel in one case or a family of cases.

A profile quantity against its mesh coordinate, one line per selected case.

Asked by where, of, nearest, sigma and uncertainty; drawn by plot.

sweep.profile("T_cool", where=dict(power=4e6, mdot=0.3)).plot()
sweep.profile("T_cool", where=dict(mdot=0.3)).plot(color="power")
sweep.profile(["CHFR", "OSVR"], where=dict(power=4e6, mdot=0.3)).plot(col="quantity")
Parameters:

  • quantity – One name or a list of names, all of one unit, each a profile (one value per cell along one axis).

  • of – The calculation(s) that own the quantity, when ambiguous.

  • where – Parameters fixed at a grid level, as a dict; a choice parameter takes one of its strings (where=dict(power=4e6, wall_law="regime")).

  • nearest – Snap where values to the nearest grid level instead of raising.

  • sigma – The multiple of stat in the envelopes; sys is added as it is.

  • uncertainty – False drops the envelopes; lower and upper equal value.

reduce(quantity, reducer, versus=None, of=None, where=None, axis=None, nearest=False, sigma=1.0, uncertainty=True, limiting=False)[source]¶

Use this to see how the worst value of a quantity moves with one parameter, or over two as a map.

Collapse a quantity per case and plot it against a parameter, against two parameters as a map, or along one field axis.

Asked by the reducer, versus, of, where, axis, nearest, sigma, uncertainty and limiting; drawn by plot.

sweep.reduce("CHFR", "min", versus="power")
sweep.reduce("CHFR", "min", versus="power").plot(color="mdot")
sweep.reduce("CHFR", "min", versus=("power", "mdot")).plot()
sweep.reduce("T", "max", axis="x")
sweep.reduce("CHFR", "min", versus="power", of=channels, limiting=True)
Parameters:

  • quantity – One name or a list of names, all of one unit.

  • reducer –

    How the cells of each case are collapsed:

    • "min": the smallest cell value;

    • "max": the largest cell value;

    • "mean": the mean weighted by cell size;

    • "where_min": the coordinate of the smallest value;

    • "where_max": the coordinate of the largest value;

    • at(z=...), at(x=...) or at(cell=...): the value of one cell;

    • a callable f(values, coords): whatever it returns.

    A scalar quantity is taken as it is. A where_* reducer gives a location and a callable an unknown value, so their results carry no limit: show_limit="line" draws nothing, and show_limit="shade" or limiting=True raises.

  • versus – A numeric parameter for the x axis, or a pair of two numeric parameters (a tuple or a list) for a map (filled contours, the limit as a contour). When the map’s reducer is the limit’s own (min for at_least, max for at_most), its limit contour is the curve required(solve_for=versus[0], versus=versus[1]) draws.

  • of – The calculation(s) that own the quantity, when ambiguous.

  • where – Parameters fixed at a grid level.

  • axis –

    Collapse a field along one axis and keep a profile along the other, instead of versus:

    • "z": collapse along z, a profile along x;

    • "x": collapse along x, a profile along z.

  • nearest – Snap where values to the nearest grid level instead of raising.

  • sigma – The multiple of stat in the envelopes; sys is added as it is.

  • uncertainty – False drops the envelopes; lower and upper equal value.

  • limiting – True keeps, per case, only the calculation (and quantity) that binds: the smallest reduced value for a limit that is at_least, the largest for at_most. The frame names it in calculation and quantity. Needs every quantity’s limit declared, all with one side and one value: values are compared as they are, so across quantities it is meaningful only when they share a limit value; use required(..., limiting=True) for quantities with different limits.

required(quantity, equals=None, solve_for=None, versus=None, reduce=None, of=None, at=None, where=None, method='linear', nearest=False, sigma=1.0, uncertainty=True, limiting=False)[source]¶

Use this to find how far a parameter can go before a quantity reaches its limit.

The value of solve_for at which the reduced quantity meets its limit, against versus.

Asked by equals, solve_for, versus, reduce, of, at, where, nearest, sigma, uncertainty and limiting; drawn by plot.

Each quantity is reduced over the mesh per case, the curve along solve_for is walked at every level of versus (and of every other free parameter), and the crossing is interpolated:

sweep.required("CHFR", solve_for="power", versus="mdot")
sweep.required("CHFR", equals=1.5, solve_for="power", versus="mdot")
sweep.required(["CHFR", "OSVR"], solve_for="power", versus="mdot")
sweep.required(["CHFR", "OSVR"], equals={"CHFR": 1.3, "OSVR": 1.1}, solve_for="power", versus="mdot")
sweep.required(["CHFR", "OSVR"], of=channels, solve_for="power", versus="mdot", limiting=True)
Parameters:

  • quantity – One name or a list of names. Each is walked on its own, so their units may differ.

  • equals – The target. None (the default) uses each quantity’s declared limit; a number applies to every quantity; a quantity name walks the difference to that quantity (equals="q_CHF"); a dict gives each quantity its own.

  • solve_for – Required. The parameter to walk along. Numeric.

  • versus – Required. The parameter on the x axis. Numeric.

  • reduce – The mesh reducer, any value reduce() takes. None uses min for a limit that is at_least and max for one that is at_most (min without a declared limit); one reducer applies to every quantity; a dict gives each its own.

  • of – The calculation(s) that own the quantity, when ambiguous.

  • at – Parameters fixed at a value, on or off the grid; off the grid, the walk is interpolated between the two neighbouring levels.

  • where – Parameters fixed at a grid level.

  • method –

    How the crossing is interpolated between grid points:

    • "linear": straight lines between them (the default);

    • "pchip": a monotone cubic through them.

  • nearest – Snap where values to the nearest grid level instead of raising.

  • sigma – The multiple of stat in the envelopes; sys is added as it is.

  • uncertainty – False drops the envelopes; lower and upper equal value.

  • limiting – True keeps, at each level of versus (and of every other free parameter), only the quantity and the calculation that bind, the smallest required value when the safe side lies below it and the largest when above. A quantity safe everywhere at that level does not bind there; one safe nowhere makes the level infeasible (its value is NaN). The frame names the binder in quantity and calculation, and the plot colours the markers by it. Needs every quantity’s limit declared, and the quantities that cross at one level safe on the same side of their crossings. What is compared is the required value of solve_for, so quantities of different units and limits combine.

Returns:

A curve whose frame has one row per crossing with lower, value, upper (the walked envelopes), filled (whether the crossing rests on an interpolated case) and safe. Every envelope is walked on its own; lower and upper are the smaller and the larger of the two walked bounds, so they bracket value whether the quantity rises or falls with solve_for, and both are missing when either walk finds no crossing. safe says where the quantity is safe:

  • "below": below the crossing, in solve_for;

  • "above": above it;

  • "everywhere": the walk never reaches the target and every solved point is safe;

  • "nowhere": the walk never reaches the target and every solved point is unsafe;

  • None: no limit is declared for the quantity.

Return type:

Result

class Result[source]¶

The answer to a question asked of a Sweep, ready to plot.

kind is one of:

  • "profile": a quantity along a mesh coordinate, from profile or reduce(axis=...);

  • "curve": a value against a parameter, from reduce or required;

  • "map": a value over two parameters, from reduce with a pair versus;

  • "field": a quantity over a two axis mesh, from field.

The fields a user reads:

  • frame: the tidy DataFrame, one row per drawn point, with the dimension columns, the x column, lower, value, upper and filled;

  • x: the column on the x axis;

  • dims: the dimensions that vary, with their levels;

  • fixed: the parameters that do not vary, with their values;

  • calculation: the calculation drawn, when there is one;

  • limits: the declared limits of the quantities drawn, when the values are the quantity’s own;

  • safe_side: for required, the side of the crossing where every quantity is safe, when it is one;

  • binding: whether limiting=True collapsed the result;

  • y: the parameter on the y axis of a map, else None;

  • holes: the unsolved cases of the selection left unfilled;

  • limit_note: why the result carries no limit, for a where_* or custom reducer, else None;

  • question: the question asked, its arguments resolved;

  • sweep: the sweep it was asked of;

  • labels: the sweep’s labels when the question was asked.

A binding frame carries a binder column naming the quantity (and quantity of calculation when calculations varied) that binds at each point. plot draws the result.

Parameters:

  • limits (dict)

  • safe_side (str | None)

plot(ax=None, color=None, style=None, marker=None, col=None, row=None, bound='nominal', band='total', errorbars=False, show_limit='line', crossing='none', style_sheet=None, labels=None)[source]¶

Use this to see the answer to a question; read frame instead when you want the numbers.

Draw this result and return (figure, axes); axes is an array for a panel grid.

Parameters:

  • ax – Draw into this axes instead of a new figure. Not with col or row.

  • color – Dimensions on colour, line style and marker. Unassigned dimensions take them in that order, quantity first. Not for a map, whose colour is the quantity, nor for a field.

  • style – Dimensions on colour, line style and marker. Unassigned dimensions take them in that order, quantity first. Not for a map, whose colour is the quantity, nor for a field.

  • marker – Dimensions on colour, line style and marker. Unassigned dimensions take them in that order, quantity first. Not for a map, whose colour is the quantity, nor for a field.

  • col – Dimensions on a grid of panels. Not for a field.

  • row – Dimensions on a grid of panels. Not for a field.

  • bound –

    Which envelope column is drawn:

    • "nominal": value (the default);

    • "lower": the lower envelope;

    • "upper": the upper envelope.

  • band –

    The uncertainty band around a nominal line. Not for a map or a field.

    • "total": one band from lower to upper (the default);

    • "split": the total band with the systematic part shaded darker inside it;

    • "none": no band.

  • errorbars – Draw the band as error bars instead of a fill. Not for a map or a field.

  • show_limit –

    How the declared limit of each drawn quantity is shown:

    • "line": a dashed line at the limit (a contour on a map or a field), nothing extra on a required result (the default). When the quantities on the axes all carry the same limit, one line in Style.limit_color is drawn for all of them;

    • "shade": adds hatching of the unsafe side; on a required result, the side of the curve where the limit is not met. Needs one quantity (or one curve, or quantities sharing one limit) per axes; each panel counts on its own. Raises when the result carries no limit for the drawn quantity (none declared, or a where_* or custom reducer), when several quantities with different limits share the axes, or on a required result whose side is unknown;

    • "none": draws nothing.

  • crossing –

    Where each curve meets the declared limit of its quantity, at its first linear crossing in x on the drawn bound:

    • "none": nothing (the default);

    • "mark": for every drawn curve, a dashed drop line in the curve’s colour from the x axis up to the limit, a marker where the curve meets the limit, and the x value printed horizontally on a row under the tick labels, centred on the line, in the curve’s colour and the label’s number format, without the unit (the axis label carries it); a value that would overlap its left neighbour on the first row drops to a second row;

    • "legend": the drop line and marker, with the x value and its unit in the legend instead of under the ticks; on a panel grid the value is printed under the ticks of each panel, as "mark" does, because the legend is shared.

    On a panel grid every panel that marks a crossing shows its own x tick labels.

    A curve that never meets its limit gets no mark. For a profile or a reduce curve only. Raises on a required result, a map or a field, and when a drawn quantity carries no limit (none declared, or a where_* or custom reducer).

  • style_sheet – A Style for the look (sizes, colours, the map’s levels, the markers of filled cases).

  • labels – Display names merged over the result’s own for this figure. An entry is a Label or a shorthand tuple; the 4-tuple (display, unit, scale, fmt) also sets how that name’s numbers print, with fmt a format spec like ".1f" or a callable on the scaled number. A name without a format prints with the style sheet’s number_format.
